## Abstract

Spam detection is a binary classification problem in which a useful system must identify unwanted messages without hiding legitimate email. This study evaluates three permitted traditional machine-learning algorithms on the UCI Spambase dataset: Logistic Regression, Gaussian Naive Bayes, and Random Forest. The dataset contains 4,601 email records represented by 57 numeric word-frequency, character-frequency, and capital-run features. Exact duplicates were removed before an 80/20 stratified split. Hyperparameter selection used five-fold stratified cross-validation on the training partition only, with spam-class F1 as the primary metric. Random Forest achieved the strongest validation result, with mean spam F1 of 0.935 and standard deviation 0.016, compared with 0.906 for Logistic Regression and 0.812 for Gaussian Naive Bayes. On the untouched test partition, the selected model achieved accuracy 0.945, spam F1 0.932, and ROC AUC 0.989. The results support a deployable second-opinion tool, while the age of the dataset and the absence of raw email text limit generalization.

**Keywords:** email spam, traditional machine learning, Random Forest, exploratory data analysis, binary classification

## I. Introduction

Unwanted email consumes attention and can carry fraud, malware, or misleading offers. A practical classifier must balance two errors: false positives can hide legitimate messages, while false negatives allow spam to reach the inbox. Machine learning is appropriate because spam is expressed through combinations of weak lexical, symbolic, and stylistic signals that are difficult to capture with one manually written rule.

This project studies the question: **what does a traditional machine-learning model need to recognize spam, the words and symbols or the style represented by capital-letter runs?** The intended use is a second opinion for a person or small team, not an autonomous mailbox action. The work is restricted to traditional supervised classification and does not use neural networks, deep learning, transformers, pretrained models, or automated model-generation systems.

The study compares exactly three algorithms under the same data split, preprocessing rules, cross-validation folds, and primary metric. It also provides a Streamlit application that loads the saved training pipeline. Feature-family ablation results are reserved for `[PLACEHOLDER]` until that experiment is run and recorded; no unverified ablation values are reported here.

## II. Methods

### A. Dataset and ethics

The UCI Spambase dataset contains 4,601 records from email messages and was created by Hopkins, Reeber, Forman, and Suermondt [1]. Each row represents one email. The feature matrix includes 48 listed-word frequencies, six character frequencies, and three capital-run length measures. The target is `spam` or `not_spam`, with `spam` treated as the positive class.

The dataset contains historical email-derived information and reflects its original collection context. It does not include the raw messages in this repository. The applicable dataset license or permission statement is `[PLACEHOLDER]` and must be confirmed before submission.

### B. Data preparation

The original data contained 4,601 rows, 57 feature columns, and no missing values. There were 391 exact duplicate rows, including three groups with conflicting labels. To prevent repeated records from crossing the train/test boundary, exact duplicates were removed before splitting and the first occurrence was retained. This produced 4,210 rows. The duplicate report is saved with the training metadata.

The data was divided into 80% training and 20% test data using stratification and random state 42. All model selection occurred within the training partition using five-fold stratified cross-validation. The test data was not used until the final model had been selected.

### C. Exploratory analysis

EDA examined class balance, feature-family scale, class-conditional means, correlations, and capital-run outliers. Five figures and written findings are generated by `src/spam_detection/eda.py` and saved under `data/processed/eda/`. The class distribution is mildly imbalanced, so stratification and spam-class F1 were used. Feature families have different native scales, motivating scaling inside the Logistic Regression and Naive Bayes pipelines. Capital totals are highly skewed; extreme values were retained because no evidence established that they were data errors.

### D. Algorithms and preprocessing

The three algorithms were selected to represent different traditional modeling assumptions:

1. Logistic Regression provides a fast linear and relatively interpretable baseline.
2. Gaussian Naive Bayes provides a probabilistic baseline with a strong conditional-independence assumption.
3. Random Forest can represent nonlinear interactions and does not require feature scaling.

StandardScaler is inside the Logistic Regression and Gaussian Naive Bayes pipelines. Random Forest receives the numeric values without scaling. Class weighting is used where supported; no synthetic oversampling is used. This design keeps preprocessing fitted within each training fold and avoids leakage.

Spam-class F1 is the primary metric because it balances the precision and recall of the positive class. Accuracy, spam precision, spam recall, ROC AUC, and confusion matrices are supporting evidence.

### E. Application

The Streamlit app loads `models/spam_detector.joblib` and does not retrain. It accepts pasted email text or a CSV containing the 57 feature columns. Text input is converted into approximate word, character, and capital-run features. CSV input is validated for required columns, numeric values, non-negative values, and frequency ranges.

## III. Results

### A. Cross-validation comparison

| Algorithm | Selected hyperparameters | Mean spam F1 | Standard deviation |
|---|---|---:|---:|
| Logistic Regression | `C=10.0` | 0.906 | 0.019 |
| Gaussian Naive Bayes | `var_smoothing=1e-8` | 0.812 | 0.017 |
| Random Forest | `max_features=sqrt`, `min_samples_leaf=1` | 0.935 | 0.016 |

Random Forest was selected because it produced the highest validation spam F1. The complete settings are recorded in `models/training_metadata.json`.

### B. Final test evaluation

The selected Random Forest was evaluated once on the untouched test partition. It achieved accuracy of 0.945, spam precision of 0.929, spam recall of 0.935, spam F1 of 0.932, and ROC AUC of 0.989. The confusion matrix was:

```text
[[482, 24],
 [ 22, 314]]
```

The first row corresponds to actual `not_spam` messages and the second to actual `spam` messages. The model therefore produced 24 false positives and 22 false negatives in the test partition.

## IV. Discussion

The validation comparison shows a clear difference among the three traditional algorithms. Random Forest performed best on the full numeric feature set, which is consistent with its ability to capture nonlinear interactions among word, symbol, and capital features. Logistic Regression was competitive and provides a useful interpretable baseline. Gaussian Naive Bayes was weaker under the selected assumptions and feature representation.

The final test result indicates strong performance on this cleaned historical dataset, but it does not establish that the model will perform equally well on modern email. The 24 false positives matter operationally because they represent legitimate messages that could be hidden. The model should therefore be used as a second opinion, with a threshold and workflow chosen by the eventual deployment owner.

The absence of raw text is an important limitation. The app's pasted-text path approximates the original feature extraction and cannot reproduce all details of the original corpus processing. The CSV path is the reproducible path for exact feature-level evaluation.

## V. Conclusion and Recommendations

This project implemented and evaluated three permitted traditional classifiers for binary email spam classification. Random Forest was selected using training-only five-fold cross-validation and then evaluated once on the untouched test set. It achieved a test spam F1 of 0.932 and ROC AUC of 0.989 on the cleaned Spambase data.
